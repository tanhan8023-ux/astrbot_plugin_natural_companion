# 自然主动聊天（AstrBot 插件）

`astrbot_plugin_natural_companion` 是一个面向单个 QQ/OneBot v11 私聊的 AstrBot 插件。
它会参考当前会话的人设、近期对话、未完话题、情绪和结构化状态，谨慎地决定是否主动找你聊天。

它**不是固定定时器**：插件没有每隔几分钟轮询发送的循环。每次用户消息只可能创建一个随机延迟、可取消的一次性主动机会；如果用户再次发消息、暂停插件、达到频率限制或模型判断不自然，消息都会被取消或跳过。

## 安装

将整个插件目录复制到：

```text
AstrBot/data/plugins/astrbot_plugin_natural_companion/
```

目录至少包含：

```text
metadata.yaml
_conf_schema.json
main.py
core.py
```

首版按 AstrBot 4.x（最低 4.5.7）和 `aiocqhttp`/OneBot v11 适配器设计。插件不接入天气、新闻、日历等外部信息。

## 使用

在目标 QQ 私聊中发送：

```text
/主动聊天 开启
```

常用命令：

```text
/主动聊天 开启
/主动聊天 暂停
/主动聊天 状态
/主动聊天 重绑
/主动聊天 清除记忆
/主动聊天 解绑
/主动聊天 测试
/主动聊天 帮助
```

也支持不带斜杠的形式，例如 `主动聊天 开启`；如果 QQ 客户端会自动把机器人昵称连在命令前，也兼容 `系尔主动聊天 开启` 这种写法。

- **开启**：把当前私聊绑定为唯一主动聊天会话。
- **暂停**：停止主动发送，并取消已经等待中的主动机会。
- **状态**：查看当前开关、心情摘要、未完话题数量和待判断机会，不显示完整提示词或聊天原文。
- **重绑**：把主动聊天会话切换到当前私聊。非绑定会话需要 AstrBot 管理员权限。
- **清除记忆**：清除插件保存的状态，不删除 AstrBot 原有会话历史。
- **解绑**：清除绑定和插件状态。
- **测试**：创建一个显式的短延迟联调机会，用于验证模型判断和 OneBot 主动发送链路；不会改变正常主动机会的延迟策略。测试期间不要再次发送聊天内容；输入状态通知和查询状态命令不会取消机会。

直接发送以下完整短句也会暂停主动聊天：

```text
别主动找我
不要主动找我
先别主动找我
暂停主动聊天
```

## 行为说明

插件保存的是轻量结构化状态，不保存完整聊天记录：

- 机器人当前心情；
- 当前情景；
- 未完话题；
- 值得后续提起的记忆线索；
- 关系氛围；
- 与主动聊天有关的用户边界；
- 最近主动消息结果。

状态会在短暂防抖后由当前聊天模型抽取。真正发送前会再次由模型判断，要求消息符合当前人设、自然简短、不责怪用户、不制造压力。

默认安全限制：

- 主动消息间隔至少 45 分钟；
- 24 小时最多主动发送 2 条；
- 默认 00:00–07:00 不主动发送；
- 同时最多存在一个待判断主动机会；
- 用户真正发送的文字、图片、表情、语音或文件会取消旧的待发送机会；
- QQ 输入状态通知（“对方正在输入”）、戳一戳、撤回通知、机器人自身回执和空事件不会取消机会，也不会更新最近互动时间；
- `/主动聊天 状态` 只查询，不会取消任务；
- 模型调用失败、返回非法 JSON 或 OneBot 发送失败时，本次机会安全结束，不连续重试。

## 配置

AstrBot WebUI 会读取 `_conf_schema.json`。可以调整：

- 主动机会随机延迟范围；
- 主动消息最短间隔和 24 小时上限；
- 安静时段；
- 状态抽取防抖时间；
- 有具体理由和自然问候的阈值；
- 是否允许没有具体话题时进行轻量问候；
- 调试日志。

## 数据位置

插件状态默认保存为：

```text
data/plugin_data/astrbot_plugin_natural_companion/state.json
```

写入使用临时文件替换，避免进程中断造成半写入文件。删除该文件或使用 `/主动聊天 清除记忆` 可以清除插件状态。

## 本地测试

纯逻辑测试不需要安装 AstrBot：

```bash
python -m unittest discover -s tests -v
python -m py_compile core.py main.py
```

OneBot v11 联调时，推荐在 AstrBot WebUI 中把 `test_delay_seconds` 保持为 10，然后在已绑定的私聊发送：

```text
/主动聊天 测试
```

约 10 秒后**开始**读取会话和调用模型，不是承诺 10 秒内送达。生成消息还需要模型响应时间；模型不可用、返回无效内容或平台发送失败时仍可能不发送。测试仍遵守暂停、安静时段、最短间隔及每日上限。测试期间不要发送新的聊天内容；可以查询 `/主动聊天 状态`，仅打开输入框或触发“正在输入”通知不会取消任务。正常使用仍然采用随机的一次性延迟，不会按固定周期轮询。

如果普通聊天后仍没有机会，发送 `/主动聊天 状态` 查看“当前情景”和“处理状态”；打开 `debug_logging` 后再查看 AstrBot 日志，可以区分模型调用失败和本次没有达到主动机会条件。


## 0.1.2：修复输入状态通知误取消主动机会

旧版仅使用 AstrBot 的私聊事件过滤器，而 OneBot 的 `notice/notify/input_status` 也可能被适配器包装成私聊事件。
因此没有发送新消息、仅触发“正在输入”通知时，旧版也会把它误记为非文本消息并取消任务。
这不是用户必须关闭输入框的问题，也不应通过停用消息防抖插件来回避。

本版在解析命令和观察对话之前检查 `message_obj.raw_message` 的事件类型，同时保留真正媒体消息的取消行为。
忽略通知时不会阻断其他插件处理该通知。新增模拟 OneBot 事件的回归测试，覆盖等待阶段、模型判断阶段、状态查询和真实媒体消息。
测试使用模型及平台替身；不等同于真实 QQ 环境已联调成功。

更新后重载插件，发送 `/主动聊天 状态`，应看到 `插件版本：0.1.2`。
触发通知后，状态会单独显示“事件过滤：…输入状态通知（不影响主动任务）”，不再冒充用户新消息。
调试日志只记录事件类别，不输出原始事件、QQ 号或消息原文。
保留原有 `state.json`，无需清空绑定或插件记忆；旧的非文本情景摘要会在下一次正常聊天抽取后更新。
